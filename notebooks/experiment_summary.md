# สรุปผลการทดลอง — Stage 2: Vertebral Fracture Classification

> เอกสารนี้สรุปการทดลองรอบแรกของ Stage 2 (การจำแนกความรุนแรงของกระดูกสันหลังยุบ
> ตามเกณฑ์ Genant) พร้อมผลลัพธ์ ข้อค้นพบ และข้อจำกัดที่ต้องพิจารณา

---

## 1. ภาพรวมของงาน

**เป้าหมาย**: จำแนกระดับความรุนแรงของกระดูกสันหลังยุบ (Genant grade 0–3) ของกระดูก
แต่ละปล้อง (T3–L5, รวม 15 ปล้อง) จากภาพ DXA

**โครงสร้างระบบ**: แบ่งเป็น 2 ขั้น

```
ภาพ DXA ทั้งภาพ
    → [Stage 1] หาตำแหน่งแต่ละปล้อง แล้วตัดออกมา (ใช้ mask จากงานของรุ่นพี่)
    → [Stage 2] จำแนกความรุนแรงของแต่ละปล้อง  ← งานหลักของโปรเจกต์นี้
```

Stage 1 ไม่ได้พัฒนาเอง — ใช้ mask ที่มีอยู่แล้วจาก special problem ของรุ่นพี่
(ใช้ชุดข้อมูล DXA เดียวกัน จากคณะแพทยศาสตร์ โรงพยาบาลรามาธิบดี) ตามที่อาจารย์
ที่ปรึกษาระบุว่าต้องการเพียง proof-of-concept ของส่วน segmentation

**ข้อสังเกตสำคัญ 3 ข้อ**

**1. การหักกระจุกตัวที่รอยต่อทรวงอก-เอว (thoracolumbar junction)** — ปล้อง T11,
T12, L1 มีสัดส่วนการหักสูงที่สุด (16.4%, 26.2%, 28.6%) รวมกันคิดเป็น **592 จาก
978 ปล้องที่หักทั้งหมด หรือ 60.5%** ทั้งที่เป็นเพียง 3 ใน 15 ปล้อง

ตรงกับความรู้ทางคลินิกที่ทราบกันดี — บริเวณนี้เป็นจุดเปลี่ยนระหว่างกระดูกสันหลัง
ช่วงอกที่ค่อนข้างแข็ง กับช่วงเอวที่เคลื่อนไหวได้มากกว่า จึงรับแรงกดสะสมมากที่สุด

**2. ปล้องบนสุดแทบไม่มีการหักเลย** — T3 และ T4 มีปล้องที่หักเพียง 2 และ 1 ปล้อง
(0.5% และ 0.2%) ซึ่งแทบไม่มีสัญญาณให้โมเดลเรียนรู้ในบริเวณนี้

**3. จำนวนปล้องต่อระดับไม่เท่ากัน** — T3 มีเพียง 384 ปล้อง และ T4 มี 648 ปล้อง
เทียบกับปล้องอื่นที่มีราว 820–830 ปล้อง เพราะปล้องบนสุดมักอยู่นอกขอบเขตภาพ DXA
(ถูกเข้ารหัสเป็น `99` และไม่มี mask)

**ผลกระทบต่อการตีความ**: การกระจายที่ไม่สม่ำเสมอนี้อธิบายว่าทำไมโมเดลจึงต้องรู้
ว่ากำลังดูปล้องไหน (ผ่าน level embedding) — ความน่าจะเป็นเบื้องต้นของการหักที่ L1
สูงกว่าที่ T4 ถึงเกือบ 150 เท่า และยังหมายความว่า**ตัวเลข recall รายปล้องในผล
การทดลองต้องอ่านควบคู่กับจำนวนตัวอย่างเสมอ** เพราะหลายปล้องมีตัวอย่างที่หัก
น้อยมากจนตัวเลขผันผวนสูง

## 3. การตั้งค่าที่ใช้ร่วมกันทุกการทดลอง

### 3.1 สถาปัตยกรรมโมเดล

```
รูป crop ปล้องเดียว → [backbone] → feature
ตำแหน่งปล้อง (T3–L5) → [level embedding 15×32] → เวกเตอร์
                              ↓ ต่อกัน
                        [head: Dropout + Linear] → Genant grade
```

**ทำไมต้องบอกตำแหน่งปล้องให้โมเดลด้วย**: กระดูกช่วงอกบางปล้องมีรูปทรงเอียงเล็กน้อย
ตามธรรมชาติ ซึ่งหน้าตาคล้ายการหักระดับเล็กน้อย การบอกว่ากำลังดูปล้องไหนช่วยให้
โมเดลแยกแยะ "ปกติของปล้องนั้น" ออกจาก "หักจริง" ได้ โดยยังใช้ backbone ตัวเดียว
ร่วมกันทุกปล้อง (ได้ประโยชน์จากการเรียนรู้ร่วมกัน ไม่ต้องแยกโมเดล 15 ตัว)

### 3.2 การเตรียมภาพ

ทำเท่าที่จำเป็นทางเทคนิคเท่านั้น **ไม่มี augmentation และไม่มี preprocessing ใดๆ**
(ตั้งใจให้เป็น baseline ที่ "เปลือย" ที่สุด เพื่อใช้เป็นจุดเทียบเมื่อเพิ่มเทคนิคทีหลัง)

1. ย่อภาพให้พอดีกรอบ โดยรักษาสัดส่วนเดิม (ไม่บีบ กันกระดูกผิดสัดส่วน) แล้วเติมขอบดำ
   ให้เป็นจัตุรัส — เรียกวิธีนี้ว่า `resize_mode="pad"` (ค่าเริ่มต้นของทุกการทดลอง
   ก่อนหน้าหัวข้อ 4.2 การทดลองที่ 6)
2. ทำภาพขาวดำให้เป็น 3 ช่องสี (backbone ต้องการ 3 ช่องเสมอ)
3. ปรับสเกลตัวเลขตามค่ามาตรฐานของ backbone ที่ใช้

ภายหลังเพิ่มตัวเลือก `resize_mode="stretch"` (ยืดภาพเต็มกรอบตรงๆ ไม่รักษาสัดส่วน
ไม่เติมขอบดำ) ตามที่อาจารย์ที่ปรึกษาเสนอให้ลอง — รายละเอียดในการทดลองที่ 6

### 3.3 การเทรน

| พารามิเตอร์ | ค่า |
|---|---|
| Loss | Focal Loss (γ = 2) + inverse-frequency class weight |
| Optimizer | AdamW, lr = 1e-4, weight decay = 1e-4 |
| Batch size | 64 (RAD-DINO ใช้ 32) |
| Epochs | 15 (early stopping, patience = 3) |
| Scheduler | CosineAnnealingLR |
| Seed | 42 (ทุกการทดลอง) |
| เกณฑ์เลือกโมเดล | **macro F1 บนชุด val** |

**ทำไมใช้ Focal Loss แทน loss มาตรฐาน**: ข้อมูลปกติมีถึง 92% ถ้าใช้ loss ธรรมดา
โมเดลจะพบว่า "ทายปกติทุกครั้ง" ก็ได้คะแนนดีแล้ว และไม่ยอมเรียนรู้ที่จะจับปล้องที่หัก

**ทำไมเลือกโมเดลด้วย macro F1 ไม่ใช่ accuracy**: ด้วยข้อมูลไม่สมดุลขนาดนี้
accuracy สูงได้โดยไม่มีประโยชน์ ส่วน macro F1 เฉลี่ยทุกคลาสเท่าๆ กัน คลาสไหนแย่
จะดึงคะแนนรวมลงทันที

### 3.4 การใช้ชุด test

ใช้ชุด test **ครั้งเดียวตอนจบ** ของแต่ละการทดลองเท่านั้น การตัดสินใจทุกอย่างระหว่าง
ทาง (เลือก epoch ที่ดีที่สุด, early stopping) ใช้ชุด val ล้วนๆ

### 3.5 กฎตัดสินใจ (ตั้งไว้ก่อนเห็นผล)

| ผลต่าง | การตีความ |
|---|---|
| มากกว่า 5 pp | น่าจะเป็นความต่างจริง |
| 2–5 pp | ยังสรุปไม่ได้ ต้องรันหลาย seed ยืนยัน |
| น้อยกว่า 2 pp | ถือว่าเสมอ |

ตั้งกฎนี้ไว้ก่อนเริ่มทดลอง เพื่อไม่ให้เผลอเข้าข้างผลที่อยากได้ภายหลัง

### 4.2 รายละเอียดแต่ละการทดลอง

#### การทดลองที่ 1 — EfficientNet-B0 + bbox crop (baseline)

จุดอ้างอิงของทุกการทดลอง ใช้ภาพที่ตัดแบบ bounding box ธรรมดา (มีพื้นหลังและขอบ
ปล้องข้างเคียงติดมาด้วย)

#### การทดลองที่ 2 — RAD-DINO + bbox crop

ทดสอบว่า backbone ที่ผ่านการ pretrain บนภาพ X-ray โดยเฉพาะ (RAD-DINO เป็น ViT
ที่ฝึกบนภาพ chest X-ray 883,000 ภาพ) จะดีกว่า backbone ที่ pretrain บนภาพทั่วไปไหม

**ผลที่ได้ให้คำตอบสองทาง**:
- macro F1 ต่ำกว่า baseline 6.1 pp (0.367 vs 0.428)
- แต่ AUC สูงกว่าเล็กน้อย (0.811 vs 0.797) และ **จับปล้องรุนแรงได้ดีกว่ามาก**
  (recall 0.771 vs 0.457)

**สาเหตุจากการวิเคราะห์ confusion matrix**: RAD-DINO ทายว่า "หัก" เกินจริงไปมาก
(ทายว่าเล็กน้อย 239 ครั้ง ทั้งที่ของจริงมี 46 ครั้ง) จึงจับ severe ได้ดีเพราะ
"ตื่นตัว" กับทุกอย่างที่ดูผิดปกติ แลกมาด้วย false positive จำนวนมากซึ่งฉุด
macro F1 ลง

**⚠️ ข้อจำกัดสำคัญ**: การเทียบนี้**ไม่เป็นธรรม** เพราะ RAD-DINO ถูกตั้งค่าให้
freeze backbone (เทรนเฉพาะ head) ขณะที่ EfficientNet-B0 fine-tune ทั้งโมเดล
เหตุผลคือข้อจำกัดของ VRAM 8GB และเวลา — รายละเอียดในหัวข้อ 6

#### การทดลองที่ 3 — EfficientNet-B0 + masked crop

เปลี่ยนจากภาพ bbox เป็นภาพที่ลบพื้นหลังออก (ทาสีดำทับทุกจุดที่ไม่ใช่ปล้องนั้น)

**ผลชัดเจนที่สุดของรอบนี้** — ดีขึ้นทั้งสองตัวชี้วัดหลัก:
- macro F1: 0.428 → 0.547 (**+11.9 pp**)
- AUC: 0.797 → 0.861 (**+6.4 pp**)

แต่เมื่อแยกดูราย grade พบว่า**ไม่ได้ดีขึ้นทุกด้าน**:

| grade | bbox | masked | ผล |
|---|---|---|---|
| ปกติ | 0.868 | 0.954 | ดีขึ้นมาก |
| **เล็กน้อย** | **0.261** | **0.196** | **แย่ลง** |
| ปานกลาง | 0.353 | 0.314 | แย่ลงเล็กน้อย |
| รุนแรง | 0.457 | 0.714 | ดีขึ้นมาก |

ตัวเลขรวมที่ดีขึ้นมาจากคลาสปกติ (ก้อนใหญ่สุด) และคลาสรุนแรง (สำคัญทางคลินิกสุด)
เป็นหลัก

**ตัดสินใจ**: ใช้ masked เป็นฐานของการทดลองที่เหลือ

#### การทดลองที่ 4 — เพิ่ม metadata (อายุ เพศ น้ำหนัก ส่วนสูง)

เพิ่มข้อมูลผู้ป่วยเข้าไปเป็น input เสริมควบคู่กับภาพ

**ผลอยู่ในโซนที่สรุปไม่ได้**: macro F1 +3.2 pp (0.547 → 0.579) ตกอยู่ในช่วง 2–5 pp
ตามกฎที่ตั้งไว้ ซึ่งแปลว่ายังแยกไม่ออกจากความผันผวนตามธรรมชาติ

**และมีสัญญาณที่น่ากังวล**:

| grade | ไม่มี metadata | มี metadata | ผล |
|---|---|---|---|
| **เล็กน้อย** | **0.196** | **0.130** | **แย่ลง** |
| ปานกลาง | 0.314 | 0.392 | ดีขึ้น |
| รุนแรง | 0.714 | 0.829 | ดีขึ้น |

**รูปแบบนี้อธิบายได้ด้วยเหตุผลเชิงโครงสร้าง**: metadata เป็นข้อมูล**ระดับผู้ป่วย**
แต่โจทย์เป็น**ระดับปล้อง** — ปล้องทั้ง 15 ปล้องของคนเดียวกันได้ metadata ชุดเดียว
กันหมด จึงบอกได้แค่ "ผู้ป่วยรายนี้เสี่ยงแค่ไหน" แต่บอกไม่ได้ว่า "ปล้องไหนหัก"
ผลคือช่วยที่ปลายสุด (severe ซึ่งมักพบในผู้ป่วยเสี่ยงสูง) แต่ไม่ช่วย — หรืออาจ
รบกวน — กลุ่มที่ต้องอาศัยการดูภาพจริงๆ (mild)

**ข้อควรระวังเพิ่มเติม**: เพศในชุดข้อมูลนี้มีหญิง 804 : ชาย 29 เกือบเป็นค่าคงที่
จึงแทบไม่ให้ข้อมูลอะไร และพบผู้ป่วย 1 รายที่กรอกน้ำหนัก-ส่วนสูงสลับกัน (154.5 กก.
สูง 54.5 ซม.) ซึ่งระบบตรวจจับและแทนด้วยค่ามัธยฐานโดยอัตโนมัติ

**สรุป**: ยังไม่นำมาใช้ — แต่ควรระบุว่า "ยังพิสูจน์ไม่ได้ว่าช่วย" ไม่ใช่
"ไม่ช่วย" ซึ่งต่างกันมากในเชิงวิชาการ

#### การทดลองที่ 5 — เปลี่ยนโจทย์เป็น binary

ยุบ grade 1, 2, 3 รวมเป็นคลาสเดียว ("เสียหาย") เหลือ 2 คลาส เพื่อลดปัญหาความ
ไม่สมดุล (จาก 40:1 เหลือ 11:1, ตัวอย่างกลุ่มน้อยเพิ่มจาก 270 เป็น 978 ปล้อง)

**ผลชัดเจนว่าช่วยจริง** — recall ราย grade (ซึ่งเทียบข้ามโจทย์ได้) ดีขึ้นทุกระดับ:

| grade | multiclass | binary | ผลต่าง |
|---|---|---|---|
| เล็กน้อย | 0.196 | 0.348 | **+15.2 pp** |
| ปานกลาง | 0.314 | 0.667 | **+35.3 pp** |
| รุนแรง | 0.714 | 1.000 | **+28.6 pp** (จับได้ครบทุกปล้อง) |

**โปรไฟล์การคัดกรอง** (จาก confusion matrix):
```
จับปล้องที่หักได้        85 จาก 132 ปล้อง  (64.4%)
สัญญาณเตือนผิดพลาด      41 จาก 1,548 ปล้องปกติ  (2.6%)
```

**แต่ mild ยังเป็นคอขวด**: จาก 47 ปล้องที่พลาดไป **30 ปล้อง (64%) เป็น mild**
ทั้งที่ยุบคลาสไปแล้ว

#### การทดลองที่ 6 — resize mode: pad vs stretch (ข้อเสนอของอาจารย์ที่ปรึกษา)

อาจารย์เสนอให้ลองยืดภาพเต็มกรอบตรงๆ (`stretch`) แทนการเติมขอบดำ (`pad`) เพราะ
Grad-CAM ในการทดลองที่ 3 พบว่าโมเดล masked บางเคสไปมองพื้นที่ดำว่างแทนตัวกระดูก
— `stretch` ตัดปัญหานี้ได้เพราะไม่มีพื้นที่ว่างเหลือเลย แต่แลกมาด้วยความเสี่ยงที่
กระดูกแต่ละปล้องจะโดนบิดสัดส่วนไม่เท่ากัน (ปล้องที่แบนจากการหักรุนแรงจะโดนยืด
แนวตั้งมากกว่าปล้องปกติ) ซึ่งอาจกระทบการวัดความสูงที่เป็นหลักการของ Genant grade
โดยตรง

ทดสอบทั้ง 2 crop variant (bbox และ masked) เทียบกับ baseline `pad` ของแต่ละแบบ:

| | bbox: pad → stretch | masked: pad → stretch |
|---|---|---|
| macro F1 | 0.428 → 0.481 (**+5.3 pp**) | 0.547 → 0.576 (+2.9 pp) |
| AUC | 0.797 → 0.771 (**−2.6 pp**) | 0.861 → 0.860 (ไม่เปลี่ยน) |
| recall ปกติ | 0.868 → 0.953 (ดีขึ้น) | 0.954 → 0.979 (ดีขึ้น) |
| recall เล็กน้อย | 0.261 → 0.130 (**แย่ลงมาก**) | 0.196 → 0.109 (แย่ลง) |
| recall ปานกลาง | 0.353 → 0.294 (แย่ลง) | 0.314 → 0.353 (ดีขึ้น) |
| recall รุนแรง | 0.457 → 0.543 (ดีขึ้น) | 0.714 → 0.800 (ดีขึ้น) |

**ผลไม่ได้ตอบง่ายๆ อย่างที่หวัง**:

- macro F1 ของ bbox ดีขึ้นเกินเกณฑ์ 5 pp (น่าจะจริง) แต่ของ masked ดีขึ้นแค่
  2.9 pp (อยู่ในโซนสรุปไม่ได้ตามกฎที่ตั้งไว้)
- **AUC กับ macro F1 ให้ทิศทางขัดกันในกรณี bbox** (macro F1 ดีขึ้น แต่ AUC แย่ลง)
  — สัญญาณว่า stretch อาจทำให้โมเดลมั่นใจผิดที่มากขึ้น แม้ทายถูกบ่อยขึ้นก็ตาม
- รูปแบบที่สอดคล้องกันทั้ง 2 variant: **mild แย่ลงเสมอ, severe ดีขึ้นเสมอ** —
  ตรงกับสมมติฐานว่า stretch ช่วยให้สัญญาณที่ชัดอยู่แล้ว (severe) ชัดขึ้นไปอีก
  แต่ไม่ได้ช่วยแยกแยะสัญญาณที่บางอยู่แล้ว (mild) เลย อาจถึงขั้นทำให้แย่ลง
- moderate ให้ผลกลับทิศกันระหว่าง bbox (แย่ลง) กับ masked (ดีขึ้น) — ยังไม่มี
  คำอธิบายที่ชัดเจนสำหรับความต่างนี้

**ข้อสังเกตทางเทคนิค**: การทดลอง masked+stretch เป็นรอบเดียวที่ไม่เกิด early
stopping เลย (`best_epoch=15` เต็มจำนวนรอบที่ตั้งไว้) ต่างจากทุกการทดลองอื่นที่
หยุดก่อนกำหนดเสมอ (epoch 4–9) — อาจแปลว่ายังไม่ถึงจุดอิ่มตัว ควรลองเพิ่ม epoch
ถ้าจะสรุปผลจริงจัง

**ยังไม่ได้ทำ Grad-CAM กับโมเดล stretch** — เป็นขั้นตอนสำคัญที่ต้องทำต่อ เพื่อ
ตรวจสอบว่าปัญหา "มองมุมดำ" ที่เจอใน masked+pad หายไปจริงตามที่คาดไว้หรือไม่ และ
เพื่อดูว่าการบิดสัดส่วนส่งผลต่อบริเวณที่โมเดลสนใจอย่างไร

#### การทดลองที่ 7 — EfficientNet-B4 (224px, fine-tune เต็ม)

ทดสอบ backbone ที่ใหญ่กว่า B0 (~19M พารามิเตอร์ เทียบ B0 ที่ ~4M) โดยตั้งใจเทียบ
กับ RAD-DINO แบบที่ควบคุมตัวแปรให้เท่ากันมากที่สุด (fine-tune เต็มทั้งคู่)

**หมายเหตุสำคัญเรื่อง img_size**: เดิมวางแผนให้ทั้ง B4 และ RAD-DINO ใช้ 380px
(สเปกทางการของ B4) เพื่อให้ทั้งคู่ใช้ขนาดภาพเท่ากันเป๊ะ แต่ระหว่างรันจริงบน RTX
4060 Ti (VRAM 8GB) พบว่าใช้เวลานานเกินกว่าที่มี (GPU ทำงาน 100% ต่อเนื่องนาน
20+ นาทียังไม่จบ 1 epoch) จึงตัดสินใจ**ลด img_size กลับเป็น 224px** เพื่อให้ทัน
เวลา — ผลที่ได้ในตารางนี้จึงมาจาก 224px ไม่ใช่ 380px ตามแผนเดิม

เทียบกับ EfficientNet-B0 + masked (baseline, macro F1 0.547):

| | B0 (baseline) | B4 (224px) | ผลต่าง |
|---|---|---|---|
| macro F1 | 0.547 | 0.553 | +0.6 pp (ถือว่าเสมอ) |
| AUC | 0.861 | 0.891 | **+3.0 pp** |
| recall ปกติ | 0.954 | 0.915 | −3.9 pp |
| recall เล็กน้อย | 0.196 | 0.239 | +4.3 pp |
| recall ปานกลาง | 0.314 | **0.588** | **+27.4 pp** |
| recall รุนแรง | 0.714 | 0.629 | −8.5 pp |

**macro F1 แทบไม่ต่างกัน แต่โปรไฟล์ข้อผิดพลาดต่างกันมาก** — B4 แลก recall ของ
severe ที่ลดลงเพื่อแลกกับ moderate ที่ดีขึ้นมหาศาล ไม่ใช่กรณีที่ backbone หนึ่ง
"ดีกว่า" อีกอันทุกด้าน แต่เป็นการ trade-off ที่ต่างจุดกัน

**ยังตอบคำถามหลัก (B4 vs RAD-DINO แบบแฟร์) ไม่ได้** — เพราะ RAD-DINO แบบ
fine-tune เต็ม (ที่ตั้งใจเทียบคู่กับ B4 นี้) **ยังไม่ได้รัน** ตัวเลข RAD-DINO ที่มี
อยู่ในตารางสรุป (แถวที่ 2) เป็นแบบ frozen backbone บน bbox variant คนละเงื่อนไข
ทั้งการ freeze และ crop variant เทียบกับ B4 แถวนี้ตรงๆ ไม่ได้เลย

#### การทดลองที่ 8 — ยุบเป็น 3 คลาส (ปกติ / เสียหายปานกลาง / เสียหายมาก)

ทดลองยุบ grade ต่างจาก binary — แทนที่จะรวม grade 1-3 เป็นกลุ่มเดียว ("เสียหาย")
ทดลองนี้**แยก severe ออกมาต่างหาก** และรวมแค่ mild กับ moderate เข้าด้วยกันเป็น
"เสียหายปานกลาง" (grade 0→ปกติ, grade 1,2→เสียหายปานกลาง, grade 3→เสียหายมาก)
ทดสอบทั้งบน `resize_mode: pad` (8a) และ `stretch` (8b) เพื่อดูว่าข้อสรุปเรื่อง
resize จากการทดลองที่ 6 ยังเป็นจริงไหมเมื่อเปลี่ยนโจทย์เป็นยุบคลาส — **นี่คือ
2 การทดลองคนละ config กัน ไม่ใช่การรันซ้ำด้วย config เดียวกัน**

| | 8a: pad | 8b: stretch | ผลต่าง |
|---|---|---|---|
| macro F1 | 0.735 | 0.729 | −0.6 pp (ถือว่าเสมอ) |
| AUC | 0.917 | 0.919 | +0.2 pp (ถือว่าเสมอ) |
| recall ปกติ | 0.970 | 0.966 | −0.4 pp |
| recall เล็กน้อย | 0.304 | **0.391** | **+8.7 pp** |
| recall ปานกลาง | 0.627 | 0.627 | เท่ากันเป๊ะ |
| recall รุนแรง | 0.714 | 0.714 | เท่ากันเป๊ะ |

**ข้อสังเกตที่มีค่า**: recall ของ moderate และ severe **เท่ากันเป๊ะทั้ง 2 config**
(แถวสอดคล้องกันทุกตัวเลขใน confusion matrix) — resize mode ไม่ส่งผลต่อการจับกลุ่ม
เหล่านี้เลยในโจทย์ 3 คลาส ในขณะที่ recall ของ mild เปลี่ยนชัดเจน (+8.7 pp) แปลว่า
ความผันผวนจาก resize mode กระจุกอยู่ที่**รอยต่อ normal-mild** เป็นหลัก ตรงกับที่
สรุปไว้แล้วในหัวข้อ 5.3 ว่าเส้นแบ่งนี้บางที่สุด — หลักฐานอิสระอีกชุดที่ชี้ไปทางเดียวกัน

**จุดที่น่าสนใจที่สุด — ทิศทางกลับกันกับโจทย์ 4 คลาส**: ในการทดลองที่ 6 (4 คลาส)
stretch ทำให้ recall ของ mild **แย่ลง** ทั้ง 2 crop variant (bbox: −13.1 pp,
masked: −8.7 pp) แต่พอยุบ mild เข้ากับ moderate ในโจทย์นี้ stretch กลับทำให้
recall ของกลุ่มที่รวมกันนั้น **ดีขึ้น** (+8.7 pp) คำอธิบายที่เป็นไปได้: stretch
อาจทำให้แยก "mild ออกจาก normal" ยากขึ้น (สัญญาณบางอยู่แล้วยิ่งเพี้ยน) แต่การ
แยก "กลุ่มที่เสียหายแบบใดก็ได้ ออกจาก normal" (ซึ่งเป็นสิ่งที่โจทย์นี้ถามจริงๆ
หลังยุบคลาส) ทำได้ง่ายขึ้น เพราะไม่ต้องแยกแยะความละเอียดอ่อนระหว่าง mild กับ
moderate อีกต่อไป — เป็นสมมติฐานที่ยังไม่ได้ตรวจสอบเพิ่มเติม

**เทียบกับ multiclass/binary**: recall ของ "เสียหายปานกลาง" (0.627, รวม mild+
moderate) อยู่**ระหว่างกลาง**ของ multiclass mild (0.196) และ multiclass moderate
(0.314) ทั้งคู่ต่ำกว่า — สมเหตุสมผลเพราะเป็นผลจากการรวม 2 กลุ่มที่มีพฤติกรรม
ต่างกัน severe recall (0.714) เท่ากับที่ multiclass ได้พอดีทั้ง 8a และ 8b (ไม่ต่าง
จากที่คาด เพราะ 3class ไม่ได้เปลี่ยนอะไรกับตัว severe เลย ยังคงแยกเดี่ยวเหมือนเดิม)

**ยังไม่ได้ทำ Grad-CAM กับการทดลองนี้ทั้ง 8a และ 8b**

### 4.3 การตรวจสอบด้วย Grad-CAM

รัน Grad-CAM บนโมเดลทั้ง bbox และ masked (การทดลองที่ 1 และ 3) เพื่อดูว่าโมเดลใช้
บริเวณไหนของภาพในการตัดสินใจ — **ยังไม่ได้ทำกับการทดลองที่ 6, 7, 8** (stretch,
B4, 3class) เป็นงานที่ต้องทำต่อ โดยเฉพาะการทดลองที่ 6 (stretch) ที่ควรตรวจสอบ
ว่าแก้ปัญหาที่พบด้านล่างได้จริงหรือไม่

**ผลที่พบ — ไม่เป็นผลดีกับ masked**:

- ในโมเดล **bbox** สีร้อน (บริเวณที่มีอิทธิพลสูง) อยู่**บนเนื้อกระดูก**เกือบทุกภาพ
  (9 จาก 12 ภาพ)
- ในโมเดล **masked** พบหลายกรณีที่สีร้อนอยู่ใน**มุมภาพที่เป็นพื้นดำล้วน ไกลจาก
  กระดูก** โดยเฉพาะในเคสที่ทายถูก เช่น ปล้อง T11 ที่ทาย severe ถูก แต่ตัวกระดูก
  แทบไม่มีสีร้อนเลย

**ข้อสังเกตที่ต้องให้ความเป็นธรรม**: บางภาพของ masked มีสีร้อนเป็นแถบตั้งที่
**ขอบซ้าย-ขวาของกระดูก** ซึ่ง**อาจไม่ใช่ข้อผิดพลาด** เพราะการวัด Genant grade
ใช้สัดส่วนความสูงที่ขอบหน้า-กลาง-หลังของกระดูก จุดที่ต้องวัดคือขอบพอดี ต้องแยก
ให้ออกระหว่าง "สีร้อนที่ขอบกระดูก" (มีเหตุผล) กับ "สีร้อนที่มุมภาพว่างๆ"
(ไม่มีความหมาย)

**สรุป**: ข้อได้เปรียบเชิงตัวเลขของ masked **ยังอธิบายด้วย "โมเดลเข้าใจกระดูก
ดีขึ้น" ไม่ได้เต็มปาก** — ต้องบันทึกเป็นข้อจำกัด

### 4.4 การทดลองที่ยกเลิกกลางคัน

**ConvNeXt-Tiny + bbox** — ยกเลิกเพราะใช้เวลานานเกินกว่าเวลาที่มี (โมเดลมี
พารามิเตอร์ 27.8 ล้าน เทียบกับ EfficientNet-B0 ที่ 4 ล้าน) เดิมตั้งใจรันเพื่อ
เทียบกับ backbone ที่รุ่นพี่ใช้ (ได้ AUC 95.13% ในงานของเขา)

## 5. ข้อค้นพบหลัก

### 5.1 Masked crop ให้ผลดีกว่า bbox อย่างชัดเจน

ดีขึ้น 11.9 pp ซึ่งเกินเกณฑ์ 5 pp ที่ตั้งไว้ **แต่ Grad-CAM ชี้ว่าส่วนหนึ่งอาจ
มาจากสัญญาณที่ไม่เกี่ยวข้องทางคลินิก** — ควรรายงานทั้งสองด้าน

### 5.2 การยุบคลาสเป็น binary ช่วยการตรวจจับได้จริงทุกระดับ

โดยเฉพาะคลาสรุนแรงที่จับได้ครบ 100% เหมาะกับการใช้เป็นเครื่องมือคัดกรองเบื้องต้น
ในทางคลินิก

### 5.3 คลาส "เล็กน้อย" (mild) เป็นข้อจำกัดเชิงโครงสร้าง ไม่ใช่ปัญหาการออกแบบ

หลักฐานจากทุกทิศทางชี้ไปทางเดียวกัน:

| วิธีที่ลอง | ผลกับ mild |
|---|---|
| เปลี่ยนแบบ crop (bbox → masked) | แย่ลง (0.261 → 0.196) |
| เพิ่ม metadata | แย่ลง (0.196 → 0.130) |
| ยุบคลาสเป็น binary | ดีขึ้นแต่ยังต่ำ (0.196 → 0.348) |
| เปลี่ยน backbone เป็น RAD-DINO | ดีขึ้นเล็กน้อย (0.261 → 0.283) |

**ข้อสรุป**: ปัญหาน่าจะมาจากตัวอย่างที่น้อยเกินไป (ชุด train มี mild เพียง 224
ปล้อง) ประกอบกับความยากทางคลินิกเองที่ mild แยกจาก normal ได้ยากแม้แต่สำหรับ
ผู้เชี่ยวชาญ — **ไม่น่าแก้ได้ด้วยเทคนิคการเทรน ต้องการข้อมูลเพิ่ม**

### 5.4 Resize mode (pad vs stretch) ส่งผลต่างกันขึ้นกับว่า mild ถูกแยกเดี่ยวหรือถูกยุบรวม

ในโจทย์ 4 คลาส (mild แยกเดี่ยว) stretch ทำให้ recall ของ mild **แย่ลงเสมอ**
ทั้ง bbox (−13.1 pp) และ masked (−8.7 pp) — สอดคล้องกับสมมติฐานว่าการบิดสัดส่วน
กระทบสัญญาณที่บางอยู่แล้วของ mild โดยตรง แต่พอยุบ mild เข้ากับ moderate ในโจทย์
3class stretch กลับทำให้ recall ของกลุ่มที่รวมกันนั้น **ดีขึ้น** (+8.7 pp) — บอกว่า
stretch อาจช่วยแยก "เสียหายแบบใดก็ได้ ออกจาก normal" (โจทย์หยาบ) ได้ดีขึ้น แม้จะ
ทำให้แยกความละเอียดอ่อนระหว่าง mild กับ moderate (โจทย์ละเอียด) แย่ลงก็ตาม —
**คำตอบว่า pad หรือ stretch ดีกว่าจึงขึ้นอยู่กับว่าจะใช้ระบบนี้ทำอะไร** (คัดกรอง
หยาบๆ vs ให้เกรดละเอียด) ไม่ใช่คำตอบเดียวที่ใช้ได้ทุกกรณี — ยังไม่ได้ตรวจสอบ
ด้วย Grad-CAM ว่าสมมติฐานนี้ถูกจริงหรือไม่

### 5.5 โจทย์ 3class เป็นจุดกึ่งกลางที่คุ้มค่าระหว่าง multiclass กับ binary

3class ให้ recall ของกลุ่ม "เสียหายปานกลาง" (รวม mild+moderate, 0.627) ที่ดีขึ้น
มากจาก multiclass เดิม (mild 0.196, moderate 0.314) เกือบเท่า binary (mild 0.348,
moderate 0.667) **โดยที่ยังแยก severe ออกมาต่างหากได้** (recall 0.714 เท่ากับ
multiclass) ซึ่ง binary ทำไม่ได้ (severe recall 1.000 ของ binary สูงเทียม เพราะ
รวม severe เข้ากับกลุ่มเสียหายทั้งหมดจนกลายเป็นงานที่ง่ายเกินไป) — 3class จึงเป็น
ทางเลือกที่รักษาความสามารถแยก "รุนแรงแค่ไหน" ไว้บางส่วน ในขณะที่ยังได้ประโยชน์
จากการยุบคลาสส่วนใหญ่ของปัญหาความไม่สมดุล

## 6. ข้อจำกัดที่ต้องพิจารณา

### 6.1 ทุกผลมาจาก seed เดียว — ยังยืนยันความน่าเชื่อถือไม่ได้

ชุด val มีคลาสรุนแรงเพียง 40 ปล้อง และคลาสเล็กน้อย 47 ปล้อง การทายพลาดเพิ่ม
เพียง 2–3 ปล้องทำให้ macro F1 เปลี่ยนได้ 2–3 pp

**ผลกระทบ**: ผลของ metadata (+3.2 pp) **อยู่ในช่วงที่แยกไม่ออกจากความผันผวน**
ยังสรุปไม่ได้ว่าช่วยจริงหรือไม่

**สิ่งที่ควรทำ**: รันซ้ำด้วย seed อื่นอย่างน้อย 3 ค่า แล้วรายงานเป็นค่าเฉลี่ย ±
ส่วนเบี่ยงเบนมาตรฐาน

### 6.2 การเทียบ RAD-DINO กับ EfficientNet-B0 ไม่เป็นธรรม

| | EfficientNet-B0 | RAD-DINO |
|---|---|---|
| การเทรน | fine-tune ทั้งโมเดล (4M พารามิเตอร์) | freeze backbone เทรนแค่ head |
| ขนาดภาพ | 224×224 | 224×224 (ทางการคือ 518×518) |
| learning rate | 1e-4 | 1e-3 |

เหตุผลของการตั้งค่าเหล่านี้คือข้อจำกัดของ VRAM 8GB (ที่ 518×518 ViT ต้องประมวลผล
1,369 ชิ้นส่วนภาพ กลไก attention กินหน่วยความจำแบบกำลังสอง) และเวลาที่มีจำกัด

**ผลกระทบ**: หาก RAD-DINO ได้ผลด้อยกว่า **อาจเป็นเพราะการ freeze ไม่ใช่เพราะ
pretrained feature ไม่ดี** — ยังสรุปไม่ได้ว่า domain-specific pretraining ไม่ช่วย

### 6.3 ยังไม่ได้ปรับ learning rate แยกตาม backbone

ใช้ lr = 1e-4 เหมือนกันทุก backbone (ยกเว้น RAD-DINO) ซึ่ง ViT มักต้องการ lr ที่
ต่ำกว่า CNN — backbone ที่ได้ผลด้อยกว่าอาจเพียงแค่ lr ไม่เหมาะสม

### 6.4 ใช้วิธี greedy sequential ablation ซึ่งสมมติว่าการตัดสินใจไม่เกี่ยวข้องกัน

เลือก backbone ตอนที่ยังไม่มี augmentation → เลือกแบบ crop → เพิ่ม metadata
ตามลำดับ วิธีนี้สมมติว่า "backbone ที่ดีที่สุดตอนไม่มี augmentation จะยังดีที่สุด
ตอนมี augmentation" ซึ่งไม่จริงเสมอไป

เป็นข้อจำกัดที่ยอมรับได้ (การทดลองทุกคู่ผสมมีต้นทุนสูงเกินไป) แต่ควรระบุไว้

### 6.5 ตัวเลข macro F1 ของโจทย์ binary เทียบกับ multiclass โดยตรงไม่ได้

โจทย์ binary เฉลี่ยเพียง 2 คลาส และมีคลาส "ปกติ" ที่ง่ายมากอยู่ด้วย ทำให้ตัวเลข
สูงขึ้นเป็นธรรมดา **ต้องเทียบด้วย recall ราย grade เท่านั้น**

### 6.6 ยังไม่ได้ทดสอบ augmentation และ image preprocessing

การทดลองทั้งหมดใช้ภาพดิบที่ผ่านเพียงการปรับขนาดและสเกลตัวเลข — ยังไม่ทราบว่า
เทคนิคเหล่านี้จะช่วยได้แค่ไหน โดยเฉพาะกับปัญหาคลาส mild

### 6.7 ข้อจำกัดของการอ่าน Grad-CAM

1. heatmap คำนวณจากตารางความละเอียด 7×7 แล้วขยายเป็น 224×224 — สีจึงเลอะออกนอก
   ขอบเขตจริงได้ง่าย
2. ดูเพียง 3 ภาพต่อคลาส ตัวอย่างน้อยเกินกว่าจะสรุปเป็นกฎ
3. Grad-CAM บอกว่า "ตรงไหนมีอิทธิพล" ไม่ได้บอกว่า "โมเดลคิดอะไร" — เป็นเครื่องมือ
   ชี้เบาะแส ไม่ใช่หลักฐานตัดสิน

### 6.8 Grad-CAM ใช้กับ RAD-DINO ไม่ได้

RAD-DINO เป็น Vision Transformer ซึ่งไม่มีชั้น convolution ให้จับ heatmap โดยตรง
ต้องใช้เทคนิคคนละแบบ (attention rollout) ซึ่งยังไม่ได้ทำ

## 7. สิ่งที่ควรทำต่อ

เรียงตามลำดับความคุ้มค่า

| ลำดับ | สิ่งที่ทำ | เหตุผล |
|---|---|---|
| 1 | รัน RAD-DINO แบบ fine-tune เต็ม (config เตรียมไว้แล้ว) | ยังไม่ได้รัน — จำเป็นต่อการตอบคำถามหลักว่า domain-specific pretrain ช่วยไหม เทียบกับ EfficientNet-B4 อย่างแฟร์ |
| 2 | Grad-CAM กับการทดลองที่ 6, 7, 8 (stretch, B4, 3class) | ยังไม่ได้ทำเลย — โดยเฉพาะ stretch ที่ต้องตรวจสอบสมมติฐานในหัวข้อ 5.4 |
| 3 | รัน masked baseline ซ้ำด้วย seed อื่น 2–3 ค่า | ทำให้ทุกข้อสรุปหนักแน่นขึ้น โดยเฉพาะผลที่อยู่ในโซน 2-5 pp (metadata, 3class-stretch) |
| 4 | ทดลอง MedDINOv3 เป็น backbone (อาจารย์ที่ปรึกษาขอให้ลอง) | สืบสวนแล้วพบว่าไม่ต้องติดตั้ง nnU-Net environment เต็มรูปแบบ (แค่ vendor โฟลเดอร์สถาปัตยกรรม + checkpoint) แต่ domain เป็น CT ไม่ใช่ X-ray ยังไม่ได้เขียนโค้ดจริง |
| 5 | ทดลอง augmentation | ยังไม่เคยทดสอบ อาจช่วยคลาสที่มีตัวอย่างน้อย |
| 6 | ทดลอง image preprocessing (เช่น CLAHE) | โครงโค้ดเตรียมไว้แล้ว |
| 7 | ปรับ hyperparameter (โดยเฉพาะ lr แยกตาม backbone) | ลด confound ในการเทียบ backbone ที่เหลือ |
